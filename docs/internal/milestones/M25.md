# M25 — macOS e2e conformance

The first graded macOS end-to-end baseline is **74 passed / 85 failed / 0 errors
/ 1 skipped of 160 selected**, in roughly 80 minutes of wall clock. M25 closes
the gap.

The measurement is done and is not this milestone's work. It cost four full
suite runs and produced a catalogue of **18 defect classes** — 16 that produce
test failures and account for all 85 exactly, plus 2 that produce none but are
real — each with a failure count, a signature, the evidence behind it, and an
explicit `[M]` measured / `[I]` inferred marking. That, together with a
recommended fix ordering and its reasoning, the confirmed-healthy properties,
and the one path that remains unproven, is recorded at
[`../macos-e2e-baseline.md`](../macos-e2e-baseline.md). **Read it first; it is
this milestone's source material and it is self-contained.**

**The headline is a capability gap, not an enforcement failure.** The macOS full
backend never installs the Lima guest's default route, so a full-backend session
has no egress at all. The suite makes this unusually legible: every `[lima]`
test that asserts traffic is *blocked* passes, and not one that requires working
egress does. The backend **fails closed** — the project's core promise is intact
and this is not a security regression — but the backend is not usable, and this
one class accounts for 24 of the 85 failures. The baseline's first recommendation
is to *confirm* the mechanism before fixing it: "installs the wrong route" and
"has no route-installing code at all" are different fixes, and only the former is
currently ruled in.

The rest of the catalogue splits roughly evenly between product defects and test
plumbing, and the baseline's fix ordering is driven by that split plus
failures-per-line-changed. Two carried-forward items sit outside the ordering:
the agent check-in startup race (a ~270 ms window, costing at most one test) and
the between-tests container reaper's removal path, which three consecutive runs
have given nothing real to catch.

One expectation to set before planning: fixing the largest class will **surface a
second crop of failures**. Once traffic flows on the full backend, the L2/L3 and
preset assertions become meaningful for the first time, and some will fail on
their own merits. A session plan that treats the 85 as a fixed budget will be
wrong about the tail.
