# M24 — macOS: operator-owned gateway VM (terminal)

On macOS the persistent gateway Lima VM belongs to the daemon account, so the QEMU process exporting 9p is `_sandboxd` — which cannot traverse an operator's home — and lite `shared:` is confined to a staging root that macOS periodically clears. Issue #82 asks for that VM to be operator-owned so `shared:` can reference real project paths. M24 delivers it, but the design puts six phases of infrastructure in front of the one user-visible change, and two of those phases remediate **active exploitable defects on `master` for which the spec is the only record**: cross-operator vmnet-slot access (§1.6), which voids a victim's egress policy with nothing in the daemon or the deny-event stream reflecting it, and a `shared:` path escape (§5.1) that yields root in the VM running every operator's gateway containers. The milestone therefore opens with an egress validation gate — the go/no-go for everything after it — because moving every enforcement point into a different trust domain must have unbypassable egress re-proven *before* the migration, not after.

Three structural properties of the plan are load-bearing and must survive replanning. **Phase 4's 4a/4b/4c split is preserved as session boundaries** (S16–S19 = 4a, S20 = 4b, S21 = 4c) with the spec's inverse revert order intact: 4a reverts daemon-side at any time, 4b only after 4a is reverted, 4c independently of both. Collapsing them would land ownership, a TCB validator boundary, the socket-group enforcement flip and an escape remediation together, where a failure cannot be attributed. **Phase 6 is distributed, not deferred** — its prerequisite item is S5, its durable bypass-resistance test is S14, its inverted cross-operator test is S20, and its doc retargeting rides each session's exit criteria, which is what "runs continuously across 1–5" means. **Phase 5 is deliberately inverted**: guest-side containment (S22) lands before declared export roots (S23), against the spec's prose order, for the reason recorded in S22's rationale.

This **is** the terminal milestone for the 2026-07-29 spec. M24-S25 produces the claim-to-code delivery map under a single conjunctive hard gate.
